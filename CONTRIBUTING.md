# Contributing to BlockDAG Phoenix

Thank you for your interest in contributing to BlockDAG Phoenix! We welcome contributions from the community.

## Getting Started

1. **Fork the repository** you want to contribute to
2. **Create a feature branch** (`git checkout -b feature/amazing-feature`)
3. **Make your changes**
4. **Commit your changes** (`git commit -m 'Add some amazing feature'`)
5. **Push to the branch** (`git push origin feature/amazing-feature`)
6. **Open a Pull Request**

## Development Setup

See individual repository READMEs for specific setup instructions:

- **[phoenix-node](https://github.com/BlockDAGPhoenix/phoenix-node)** - Go development
- **[phoenix-explorer](https://github.com/BlockDAGPhoenix/phoenix-explorer)** - TypeScript/Node.js development
- **[phoenix-sdk-js](https://github.com/BlockDAGPhoenix/phoenix-sdk-js)** - JavaScript/TypeScript development

## Code Style

- **Go**: Follow [Effective Go](https://go.dev/doc/effective_go) guidelines
- **TypeScript/JavaScript**: Use ESLint configuration from repository
- **Python**: Follow PEP 8 style guide
- **Solidity**: Follow [Solidity Style Guide](https://docs.soliditylang.org/en/latest/style-guide.html)

## Testing

- Write tests for new features
- Ensure all existing tests pass
- Aim for high test coverage

## Pull Request Process

1. Update README.md if needed
2. Add tests if applicable
3. Ensure all tests pass
4. Update CHANGELOG.md if applicable
5. Request review from maintainers

## Reporting Issues

- Use GitHub Issues for bug reports
- Use GitHub Discussions for questions and feature requests
- Include as much detail as possible (OS, version, steps to reproduce)

## Code of Conduct

Please read and follow our [Code of Conduct](CODE_OF_CONDUCT.md).

## Questions?

- Check the [Documentation](https://github.com/BlockDAGPhoenix/phoenix-docs)
- Open a [Discussion](https://github.com/orgs/BlockDAGPhoenix/discussions)
- Check individual repository READMEs

Thank you for contributing! 🚀
